## Release-time remediation

Initial Windows CI 39365312819 failed at the execution journal's directory
`fsync` with `EPERM`; its subsequent vector test also reached the 60-second
process deadline. Commit `252e258` fixes Windows directory-flush compatibility,
adds file/directory I/O-failure and recoverable-checkpoint coverage, and makes
PowerShell's multi-command steps stop on their first native-command failure.
Windows vector regressions retain a bounded three-minute deadline; other
platforms retain one minute. The successful Windows retry completed all source
checks, built-in model and vector probes in 52 seconds.

The file is flushed before atomic replacement on every platform. Windows does
not perform the additional POSIX directory sync, so equal directory power-loss
durability is not claimed. File flush errors and supported-platform directory
flush errors still fail visibly. The relevant Windows API requires a writable
handle: [Microsoft FlushFileBuffers](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-flushfilebuffers).

The initial unpublished draft tag was advanced from `eed2341` to the verified
fix commit using a lease against the tag created in this release turn. No
existing public release tag or unrelated branch was rewritten.
