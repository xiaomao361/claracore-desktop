当前页面依次展示：

1. 累积时间和四个语义数字；
2. 最近里程碑；
3. Agent 参与；
4. Memoria、共同线、InnerLife 三组完整计数；
5. 一个折叠的“高级数据”，其中混有生命周期计数和 Memory Controller 事件。

这些数据已有明确且经过测试的定义，见 `docs/TRACE_PAGE.md`。重新设计不能为了视觉效果改变统计语义，也不能把未确认事件提升为里程碑。

## 为什么需要重新审查

当前页面已经克制、只读且数据真实，但还没有完全采用 0.6.8 新设计语言：

- 它更像“跨模块统计页”，还不够像事情逐渐留下的痕迹；
- 页面没有解释痕迹从原始事件到可读结果的形成过程；
- 三组模块计数回答的是“有多少”，不一定回答“留下了什么”；
- “高级数据”仍是单个折叠区，混合了多个阅读目的；
- Memory Controller 属于回召证据或技术诊断，是否应成为痕迹页主体的一部分需要重新判断；
- 痕迹与日志的边界虽然写在产品契约里，但页面表达还可以更明确。

## 下一步先回答的问题

不要先写代码。先用当前数据和产品定位回答：

### 1. 人看完痕迹页应该知道什么？

建议从这个候选答案开始检验，而不是直接接受：

> ClaraCore 和用户共同维护的世界，最近有哪些东西真正形成、被延续或再次发生了作用。

如果实际数据不足以支撑“最近”或“再次发生作用”，应缩小表述，不制造生命感或因果关系。

### 2. 痕迹是怎样形成的？

需要从真实读模型核对一条可见流程。候选结构是：

`各模块留下可归属的事件 → 按时间与对象形成关联 → 只有满足证据边界的内容成为可读痕迹 → 人可下钻到来源证据`

这只是设计假设。必须检查 `system.js` 当前查询是否真的存在“关联”和“形成”步骤；若没有，不应画成已经运行的系统流程。

### 3. 痕迹与日志怎样分工？

- 痕迹：共同世界中形成了什么、谁参与、什么被延续或再次使用；
- 日志：工具调用、运行状态、耗时、错误和原始诊断。

Memory Controller 的逐事件记录更接近日志或 Memoria 的回召证据。若仍留在痕迹页，应有明确的人类阅读理由，而不是因为数据已经存在。

## 推荐的实施顺序

### 第一小步：审查，不改数据层

1. 用当前测试数据打开痕迹页并截取宽屏、窄屏、浅色、深色状态；
2. 对照 `UI_DESIGN_LANGUAGE.md` 标出总览、流程、主要内容、详情、诊断五层；
3. 列出每一块让人获得的信息，以及重复、缺失或混层之处；
4. 先提出新的页面骨架，再决定是否需要读模型增加数据。

### 第二小步：只重排已有事实

优先尝试不改 schema、不改统计定义的页面重组。可考虑：

- 保留安静的时间跨度总览，但让文字先于数字；
- 在总览后放置“痕迹怎样形成”的真实流程；
- 将里程碑和实际复用/延续证据作为主要阅读内容；
- Agent 参与只描述共同留下，不排名、不评分；
- 将完整计数移到“了解构成”一类次级入口；
- 用统一详情阅读层替代不断展开的高级折叠区。

这不是固定视觉稿。若真实数据不支持某一层，应删除该层而不是伪造内容。

### 第三小步：再判断是否补读模型

只有页面已经明确需要回答、而当前数据无法回答的问题，才考虑修改 `system.js` 和快照。新增字段必须有：

- 明确的人类问题；
- 可维护的事实定义；
- 空状态与边界定义；
- 独立测试；
- 不把静态计数推断成行为或因果。

## 验收标准

- 第一屏能用一句话回答痕迹页的用途，而不是先让人读指标。
- 运作流程紧跟总览，并且每个节点都能由当前代码或数据证明。
- 主页面内容有上限，历史增长不会让页面无限变长。
- 痕迹与日志、回召证据和技术诊断的边界清楚。
- 没有层层折叠或多个局部滚动条；完整对象进入统一详情阅读层。
- 页面保持只读，选择和查看不会改变生命周期状态。
- 宽屏、900px 窗口、浅色和深色下无横向溢出，固定动作位置稳定。
- `npm run test:trace`、`npm run test:phase4:trace-ui`、`npm run test:responsive-layout:ui`、`npm run test:ux:polish` 和 `npm run check` 通过。

## 不要做

- 不要把痕迹做成使用时长、打卡、排行榜或活跃度仪表盘。
- 不要为了“有故事感”声称 ClaraCore 是生命体或产生未经证实的情绪。
- 不要把日志错误、调用次数或所有最近事件自动提升为痕迹。
- 不要复制三个核心模块的外壳；复用阅读逻辑，保留痕迹自己的时间与积累隐喻。
- 不要在当前脏工作树上执行清理、回退或覆盖式 Git 操作。
