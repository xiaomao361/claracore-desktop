# ClaraCore 页面设计语言

## 核心哲学

ClaraCore 维护的不是一组功能，而是 Clara 和用户共同拥有、能够被继续的世界。页面的职责不是把数据库字段摆给人看，而是让人理解这个世界留下了什么、正在怎样变化，以及系统为什么得出眼前的结果。

每个模块都先回答两个问题：

1. 人看完这一页，应该明确知道什么？
2. 这个模块从输入到结果究竟怎样运作？

展示形式必须由这两个答案反推，而不是由现有接口、数据表或调试输出的形状决定。一个字段存在，不代表它应该出现在主页面；一个过程很重要，也不代表要把所有技术步骤同时摊开。

这套语言追求的是可理解、可解释和克制，而不是“信息很多”或“看起来像专业后台”。

同一原则也适用于页面背后的 Agent 与数据接口：**默认最小充分，按明确范围逐层展开；显式请求仍然有界。** 页面上的“理解 → 查看 → 核验”，对应接口中的 catalog / resume / context / full。主页面没有展示的完整历史，不应因为接口调用而默认进入 Agent 上下文；存储完整不等于交付完整。

当前接口契约见 [CONTEXT_DELIVERY.md](./CONTEXT_DELIVERY.md)。

## 页面阅读契约

每个模块都应提供三个逐层深入、但不互相纠缠的阅读层：

- **理解**：第一屏直接给出人的结论、当前状态和最重要的对象。
- **查看**：用卡片、索引或时间线浏览具体内容；完整详情进入同一个阅读层。
- **核验**：原始配置、诊断记录和 JSON 只在需要核对时出现，仍保持完整可读。

页面还应把模块的真实流程变成可见的设计结构：输入、处理、形成结果、决定去向，以及人在什么位置能够介入。流程节点必须来自真实状态或记录，不能只是装饰图。

三个核心模块采用同一阅读顺序：

1. **这是什么**：总览、当前状态或当前关注点；
2. **它怎样运作**：紧跟总览展示真实流程；
3. **现在留下了什么**：筛选、索引、卡片或时间线；
4. **为什么是这样**：进入统一详情阅读层查看完整证据；
5. **底层是否正常**：诊断和原始数据留在最深层。

一致的是阅读逻辑，不是机械复制同一种页面。Memoria 可以像知识架，Continuity 应当像延续中的线，InnerLife 可以像私人笔记；它们不需要都长成相同的仪表盘。

## 信息层级与组件选择

先判断人要获得什么，再选择组件：

| 阅读目的 | 首选表达 | 不应默认使用 |
| --- | --- | --- |
| 快速理解当前状态 | 一句话结论、少量关键数字、明确状态 | 一屏指标卡、字段表 |
| 理解底层机制 | 真实流程、状态路径、带当前数量的节点 | 装饰性流程图、参数清单 |
| 浏览少量当前内容 | 有呼吸感的卡片 | 密集表格 |
| 浏览持续增长的历史 | 紧凑索引、时间线、分页或“查看全部” | 无限增长的大卡片 |
| 阅读完整对象 | 单一详情弹窗或阅读层 | 多层折叠、多个小滚动框 |
| 排查技术问题 | 有解释的诊断卡、完整原始记录 | 主页面直接展示 JSON |

卡片不是默认答案。只有当对象本身值得被逐个阅读、数量受控且彼此独立时才使用卡片；历史归档和大量记录更适合索引。

## 通用规则

- 摘要有明确上限。内容增长时，主页面不随数据库无限变长。
- “待处理”适合少量、有呼吸感的卡片；“历史记录”适合紧凑索引或时间线。
- 一条内容只在一个统一详情阅读层中展开；不使用层层折叠和多个局部滚动条。
- 列表预览可以截断，详情应通过一个明确对象继续读取。单个对象仍异常巨大时使用分页、分块或 artifact；原始 JSON 不塞进看不全的小框。
- 参数先解释它会造成什么行为，再提供原始值用于核验。
- 页面上的流程既要说明系统逻辑，也要显示当前这次运行落在哪一步。
- 只读页面的交互只用于阅读和导航，不能悄悄改变生命周期状态。
- 视觉隐喻应服务模块心智模型，避免所有页面都长成相同的后台仪表盘。
- 选择只改变阅读对象，不应重排列表、激活对象或改变归属，除非页面明确就是编辑界面。
- 全局状态和对象状态必须在布局上分离，不能因为当前选择而让全局配置看起来属于某个对象。
- 长内容只保留一个滚动上下文。外层弹窗可以滚动，正文内部不再制造多个滚动条。
- 固定动作放在稳定位置。关闭、返回、筛选和“查看全部”不随内容长度漂移。
- 跨整个模块生效的阅读范围选择（例如智能体视角）固定放在页面状态之后、总览之前；三个核心模块使用同一位置、标签层级和控件样式，不与模块内部的搜索或对象操作混排。
- 空状态要解释这里本来会出现什么；只读页面不为了填满空间而制造无意义内容。
- 主路径文案直接说明对象、状态或动作。设计边界不写成反复出现的“不是”“不会”“不需要”。
- 安全后果、数据语义和诊断边界仍需明确，但只在相关操作或证据旁出现一次。

## 视觉与交互语法

- 页面开头使用安静的总览面，标题回答人的问题，数字只承担证据而不是主角。
- `HOW IT WORKS` 类流程紧跟总览，并在三个核心模块保持相同层级。
- 主页面使用留白建立分组；分隔线只用于确实需要区分的历史项和证据层。
- 首页之外的主模块共享一个连续页面阅读面；普通章节不再各自占用大卡片。
- 首页优先回答当前共同线和最近可验证活动；待消化、待判断或待分享的 InnerLife 内容不在首页提前展示。
- 卡片只承载独立对象、浏览器或操作区，不用于重复包装页面章节。
- 绿色表示 ClaraCore 的稳定、可延续状态；其他颜色只有在表达不同语义时使用，不用于装饰。
- 只读状态必须可见，但不反复提醒。控件仍需保持清晰的可点击外观与键盘焦点。
- 详情弹窗拥有固定头部、稳定右上角关闭按钮、完整正文和单一滚动路径。
- 窄窗口按内容断点重排，不能依赖桌面宽度隐藏关键动作，也不能产生横向滚动。

## 各模块的人类问题与可见流程

| 模块 | 人看完应知道 | 页面应表达的运作逻辑 |
| --- | --- | --- |
| 首页 | ClaraCore 当前是否正常、最近有什么值得注意 | 各模块状态如何汇聚成整体状态 |
| Memoria | 长期记住了什么、一次对话为什么会或不会带回记忆 | 智能体明确写入 → 标签、关系与状态链组织 → 判断是否需要历史 → 检索并检查相关性 → 有证据时返回上下文 |
| 共同线 | 我们共同走到了哪里、确认了什么、下一次从哪里接上 | 进展发生 → 更新共同理解 → 形成当前位置 → 交给下一次会话 |
| InnerLife | 最近在想什么、哪些说过、为什么会或不会分享 | 材料进入 → 后台消化 → 形成念头 → 判断场合 → 留下或带入对话 |
| Gateway / 智能体接入 | 哪些入口可用、请求最终去了哪里 | 请求进入 → 身份与权限判断 → 路由 → 返回结果 |
| 痕迹 / 日志 | 最近发生了什么、问题在哪里 | 事件产生 → 关联成链 → 聚合为可读事件 → 下钻证据 |
| 设置 | 当前规则会怎样影响系统 | 配置选择 → 生效范围 → 运行影响 → 验证结果 |

这些是迁移契约，不代表所有模块已经完成改造。新页面与后续优化都应按此检查。

“痕迹”和“日志”必须保持边界：痕迹说明这个共同世界怎样逐渐形成，日志用于排查运行时发生了什么。技术调用次数、错误栈和原始请求不应因为可统计就自动成为人的痕迹。

## Memoria 参考样板

Memoria 使用“长期知识架 + 回召证据路径”的表达：

- 主页面先回答长期保留了什么，并用有限卡片维持可读规模；
- 回召不是一个笼统的“命中”，而是依次区分需要历史、发起检索、候选相关、通过门槛与实际返回；
- 观察模式会运行判断与检索，但不把记忆带入回答，页面必须明确显示这个证据边界；
- 标签、关系图和完整记录都进入统一阅读层，不在主页面堆叠技术结构或局部滚动区。

## 共同线参考样板

共同线使用“稳定线索引 + 连续位置路径”的表达：

- 线是可长期延续的上下文对象，不是任务卡、聊天摘要集合或智能体角色；
- 主页面直接解释进展如何成为共同理解、当前位置和下一次的起点；
- 选择一条线只改变阅读对象，不激活、不重排，也不改变线的归属；
- 智能体上下文是跨线生效的全局角色层，与当前选择的线严格分离；
- 完整线列表、形成证据和已走过的线进入统一阅读层，主页面只保留当前延续所需的信息。

## InnerLife 参考样板

InnerLife 使用“私人笔记 + 归档索引”的表达：

- 尚未分享是少量、留白充足的念头卡片；
- 已经分享是紧凑的历史索引；
- 运作流程直接出现在主页面，并可进入对应记录；
- 运行状态、分享规则、技术诊断是三个目的明确的入口；
- 所有正文、配置和诊断共用一个完整详情阅读层。

它不模拟人的情绪，也不使用装饰性的对话气泡；“内心感”来自阅读节奏、内容层次和念头从形成到分享的真实过程。

## 页面审查清单

开始设计或审查一个模块时，按顺序回答：

1. 用一句话写出“人看完应该知道什么”。
2. 写出真实的数据与状态流，不确定的步骤先查代码和数据，不用视觉图补猜测。
3. 标出总览、运作流程、当前内容、完整详情和技术核验分别放在哪里。
4. 给主页面每类内容设数量上限，并定义增长后的去向。
5. 检查选择是否只改变阅读范围，全局状态是否仍保持全局。
6. 检查是否只有一个主要滚动上下文，详情是否能够完整阅读。
7. 在宽屏、窄屏、浅色和深色模式验证阅读顺序、溢出和固定动作。
8. 最后再问：这个页面像它所表达的模块吗，还是又变成了通用后台？

## 0.6.9 当前样板

截至 0.6.9 的当前工作树，Memoria、共同线、InnerLife、痕迹、日志、智能体接入和设置已按以下顺序对齐：

`总览 / 当前状态 → 运作流程 → 筛选与主要内容 → 深入阅读 → 技术核验`

首页保持总控台形态；其余主模块使用统一的连续阅读面，并通过内容结构表达各自差异。
