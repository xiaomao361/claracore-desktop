## 主线 A：sqlite-vec

### 范围与设计

1. 锁定一个 sqlite-vec 发行版本并记录平台原生文件与校验值。扩展仍处于 pre-v1，不能依赖未锁定的 main API。
2. 保留 `memory_embeddings` 的原始向量及 provider/model/dimension/status 等信息；首版 vec0 是可重建的检索投影。不要直接删除原始数据或要求用户重新生成所有 embedding。
3. 按向量空间隔离查询：provider、model、dimension 必须同时匹配。固定维度 vec0 的表/分区策略由兼容性实验确定，避免为不同维度硬塞同一列。模型切换和旧向量失效必须可解释。
4. 优化目标是减少 JS 反序列化、数据传输和距离计算。文档所指 vec0 KNN 不等于已经获得 ANN 的规模收益；本版不引入实验 ANN、量化或新 embedding 模型。
5. 当前选择：原始向量留在主库；独立的进程私有缓存库保存 vec0，随 ProductDatabase 关闭清理。主库的普通 SQLite revision triggers 捕获 embedding 增删改；搜索在同一事务内同步变更空间并查询，源版本竞争返回可识别失败。覆盖重嵌入、更新、删除、恢复及批量导入，不把部分索引当完整搜索。后续如改成后台增量同步，另行定义 building/ready/failed 与切换条件。

### 必须保持的搜索语义

- 遍历整个合格集合；输出数量上限不得变成按年龄或扫描页数截断的检索范围。
- 保留 Agent 标签过滤、current/historical/all 语义、restricted 边界和 embedding ready 条件。
- 先在完整合格集合上求 top-K，不能先取全库 K 条再事后过滤导致漏召回。评估 vec0 实际支持的过滤条件和 JOIN 限制。
- 保留 cosine 分数口径、`0.55` 阈值和向量最多 10 条；明确 cosine distance 到 similarity 的转换。验证 float32 转换、阈值边界和并列结果顺序。
- 保留关键词命中优先、keyword+vector 合并、状态注解和已有显式 neighbors 返回契约。不是借迁移重排搜索产品规则。
- 验收预期同时依据现有产品规则和代表案例；旧算法用于对照，不把历史 bug 固化成正确答案。

### 安全迁移与失败处理

- 在旧版数据库的隔离副本执行版本化、可重入迁移；记录源记录数、有效向量数、投影数、异常条目和抽样向量/查询对应关系。
- 无效 JSON、空向量、非有限数、维度错误、embedding 非 ready 分别保留可区分结果；不静默丢行后报告成功。
- 扩展加载失败或迁移中断时，不破坏基础 Memory 读写。仅在原始向量搜索仍完整且正确时使用显式可识别的旧引擎 fallback；否则返回可识别的失败/部分结果，不能伪装成正常零命中。
- 恢复安全延续 `core/runtime/backup.js` 现有验证门槛。当前独立缓存方案不把 vec0 或 shadow tables 写入主库备份；验证原始向量完整保存、隔离恢复后缓存重建。实际替换唯一数据前遵守 AGENTS.md 的精确可恢复备份要求。
- 旧版程序能否打开含 vec0 的新库需要实测，不能因保留原表就声称可回退。回退方案必须说明升级后新增数据的去向；仅恢复升级前备份会丢失其后的写入，不能称为无损回退。

## 主线 B：MCP 2026-07-28

### 哪些新特性对我们有用

| 新能力 | ClaraCore 的直接用途 | 0.7.0 决策 |
| --- | --- | --- |
| 无状态请求、逐请求版本及能力 | 降低初始化/连接状态依赖，适合本地多 Host 调用 | 实现现代核心，保留业务 Shared Line 和 InnerLife session |
| server/discover | Host 能明确发现支持版本、能力和身份 | 实现并做真实 Host 验证 |
| 确定性工具目录与缓存提示 | 减少重复目录传输，为 Host 缓存创造条件 | 稳定排序、private 缓存、有限 TTL；收益由 Host 是否采用决定 |
| 标准方法/工具请求头 | 统一路由校验，方便识别请求与排查调用 | 校验 header/body 一致性；不把工具名或 clientInfo 当认证 |
| resultType 和标准错误 | 明确普通完成结果、版本不支持和请求不一致 | 实现当前支持能力所需结果与错误契约 |
| MRTR / Tasks / 订阅 | 将来可承载补充输入、长任务、变更通知 | 本版不新增这些产品流程，也不宣称支持未实现扩展 |

本版聚焦现代工具调用核心。OAuth 服务、自动审批、模型 Sampling、后台任务平台和页面重做均不在范围。

### 接入原则

1. 复用并审查历史协议适配器，再接入当前工具处理与返回预算；不要仅改版本常量。以正式规范和 schema 为准复核历史实现。
2. 现代请求不依赖 initialize；提供 server/discover、逐请求元数据、resultType、缓存字段及规定的 HTTP headers。错误至少覆盖 header mismatch `-32020`、不支持版本 `-32022`，其他依正式规范落实。
3. 保持 `2025-06-18` legacy 路径；unsupported 版本不得原样回显为已支持。新旧响应分别按对应 schema 校验，不承诺未经验证的其他版本。
4. 保留 localhost 默认端口 `50668`、Bearer、Origin 保护、HTTP 来源 Agent 身份、Trace 和 backpressure；端口 0 仅用于隔离测试。
5. 标准 MCP 传输 session 的取消，不意味着删除业务 sessionId、Shared Line 或 `X-ClaraCore-Session-ID` 的兼容语义。
6. 工具目录缓存必须隔离认证主体、tool profile、语言等实际会改变目录的上下文；不允许跨 Agent 泄漏。目录或配置改变时使旧缓存失效，或以保守 TTL 控制陈旧；不会实现的订阅不得宣告。
7. 断线后的重发不能默认认为所有写工具都可安全重试。检查 Memory 创建、link、share 状态等写入的重复副作用；如不能安全重试，保留可检查的操作结果与明确重试边界。
8. 历史用户确认 stdio 不再使用，旧实现将其移除；当前产品又包含 stdio。B0 先核对现有 Host 配置与打包依赖后沿用 HTTP 主线，不能仅因历史删除记录直接移除当前回退路径。若本版保留 stdio，明确它的版本范围并保证 legacy 可用；移除前形成依赖核查与迁移说明。
