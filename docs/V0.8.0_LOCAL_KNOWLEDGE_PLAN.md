## 产品闭环

ClaraCore Desktop 管理用户选定的本地 Markdown 知识库。Agent 从用户主动提供的材料，或一个实质话题结束后的可复用理解中，判断是否值得收录，核对来源，整理完整小节与关联。Desktop 提供同一条受约束的收录、阅读和检索通道，使一次收录可以从对话追溯到实际 MD、关联段落和可打开的阅读结果。

Markdown 文件是正文的唯一权威副本。Desktop 保存目录设置及可重建的索引、阅读缓存和必要的操作状态，不在产品数据库中保存另一份正文。切换目录不移动、复制或覆盖旧目录。`/Volumes/E61/Knowledge` 是首个真实样例，不是默认写死的产品路径。旧 Memoria 知识卡及来源原件保留，逐项建立指针或关联，不批量迁移。

### 职责

| 参与者 | 负责 | 边界 |
| --- | --- | --- |
| Agent | 选择有复用价值的材料；区分来源陈述、Agent 提炼和用户明确立场；决定补充旧文或新建；按意思分节；阅读关联两端后写有意义的正文链接 | 检索相似度只是候选；不能把未确认观点写成用户事实，也不自动把 InnerLife 念头写成知识 |
| Desktop 知识服务 | 管理一个当前目录；提供浏览、读取、检索、收录和状态接口；校验路径、锚点、链接、冲突与写入；更新可重建索引，返回可追溯的结果 | Agent 的正常收录经服务完成，不能靠提示词纪律保证目录与写入安全；不监听所有对话或浏览历史 |
| Desktop 页面 | 让用户选择目录、阅读 MD 和段落关联、查看最近收录及待整理项目、打开检索命中并看到索引/链接错误 | 日常明确的低风险整理不要求逐篇弹窗批准；归属、范围或关键结论冲突交由用户判断 |

外部编辑器对已选目录的修改仍可读取。Desktop 发现正文变化后应标出索引过期并提供重建路径；不能继续把旧索引当作当前结果。Agent 的收录完成回执需要指向实际文档或段落，不以“已生成草稿”冒充已入库。

## 工作顺序

每项以可运行的最小纵向闭环完成，再进入下一项。阶段中的接口名、内部模块拆分由当前代码结构决定；本计划固定行为和验收，不预先锁定实现类名。

### 0. 产品与收录契约

- 明确 Knowledge 是有来源、可再次阅读和讨论的资料；Memoria 是关于用户及共同经历的已确认事实、偏好和决定；Shared Line 管当前工作位置；InnerLife 保持待核实的自身想法。更新 [定位](POSITIONING.md) 中把 `formed knowledge` 全放进 Memoria 的旧表述。
- 统一主动入库和选择性被动收集的处理流程，不增加后台采集。首版一个当前目录；MD 手工编辑仍可使用外部编辑器。
- 定义收录结果至少包含：目标相对路径、段落锚点、来源与日期、观点归属、实际写入状态、链接检查状态和索引状态。目录不可用、写入失败、校验失败、索引失败必须可区分；“写成了 MD，但索引未更新”不能报告为完全成功。

验收：文档中的角色、入口、权威数据和完成条件一致；不得再把收录列为纯阅读/检索之后的可选附属功能。

### 1. 目录与只读底座

- 选择一个本地知识目录后直接校验并保存；可单独移除目录设置，均不移动或删除原文件。从目录读取 `notes/`、`topics/` 等现有 MD。路径从 Electron 主进程或可信服务端校验，不接受相对路径、符号链接或 `..` 越界访问。
- 按稳定小节锚点读取，提取正文链接并推导反向链接；列表默认只给有用的预览，选中后读取完整的有界小节。
- 区分未选择、磁盘未挂载、无权限、空库、文件/链接异常、索引过期。此阶段对知识正文只读，不触碰真实库的原文件。

验收：以 E61 现有库的只读副本和缺盘等隔离样例验证目录、段落和链接模型；不依赖另一个项目的绝对代码路径才能在打包应用中运行。

2026-09-22 源码进度：已加入 Desktop 自有的只读目录/段落/正反链接服务、分页 IPC 和设置页单目录选择。隔离样例覆盖越界、符号链接、空库、缺盘、配置损坏、断链与锚点；对 E61 真实样例只读核对了 43 篇目录项及一个文档的段落/链接，段落数量与现有工具一致。`npm run check` 通过。设置页的实际选目录交互、打包运行与用户点击验收仍待后续验证；尚未写入真实知识正文。额外的 `test:shell` 在未修改的 HEAD 快照上出现相同的视图刷新计数失败，不能把它归因于本次知识改动。

### 2. 收录通道与一次真实整理

- Agent 使用 Desktop 提供的收录接口提交拟稿或对现有文档的补充，包含来源、归属、固定锚点、关联理由和目标文档。用户主动交付材料与选择性被动收集走同一通道。
- 服务在实际写入前给出目标与变更预览，检查并发修改、路径边界、重复锚点和链接目标；写入要可恢复，不允许用覆盖掩盖冲突。候选链接可由检索提出，但 Agent 阅读两端后才写入。
- 写后重新读回目标段落，检查链接，更新索引或明确标出索引失败；返回文档指针和各阶段状态。价值明确但尚未整理完的材料可进入 `inbox/`，不进入正文向量索引。

验收：用一段实际讨论在隔离知识库中完成“检索旧文 → 整理新/旧 MD → 建立一个经核对的段落链接 → 写后读回 → 反向链接 → 收录回执”。失败和冲突样例不改变唯一正文。

2026-09-22 源码进度：收录服务支持新建与追加完整小节，预览返回准确增量和绑定当前目录/调用者的临时 token；提交复核正文与引用文件哈希，保留追加前恢复副本并读回验证。Agent 的 MCP 入口与 Electron IPC 共用服务。来源、日期、观点归属、固定锚点、关联理由落在 MD 中；回执区分正文、链接和索引状态。结构索引只保存哈希/指针，可显式重建并检测外部编辑过期；语义向量尚未实现。`inbox/` 支持保留原因和下一步，不进入正文索引。详见 [收录契约](KNOWLEDGE_INTAKE.md)。

隔离验收以本次讨论的两条认识完成：字面检索旧文、读小节、提交带关联的新文、读回及反向链接；另测追加恢复、重复锚点、路径越界、来源变化冲突和索引失败部分完成。真实 HTTP MCP 临时实例完成认证工具发现、预览/提交/读取，确认知识正文不会存入 Gateway trace 数据库，失败调用记为 error。未启动或改动用户的实时 Desktop，未写真实 E61 正文；人的知识页面和打包/交互验收仍在后续阶段。

### 5. 可选 Jev 接入与统一回召

2026-09-22 顺序修正：此前直接进入 Jev shadow，遗漏了 Desktop 自有调用适配与用户配置。现有独立 kb.py 的接入不等于 Desktop 已支持 Jev。以下为修订后的实施顺序；源码进度见阶段末。

#### 5A. 无 Jev 的完整检索基线

- 自动回召已触发、且未明确指定领域时，对已启用且可用的 Memory / Knowledge 都做本机向量候选检索；明确指定领域或精确/混合模式时尊重调用者选择。
- “全部”指检索可用领域，不是全部正文投递，也不表示每条闲聊都检索。候选仍需相关性阈值、去重和共同上下文预算；允许无命中、不投递。
- 向量模型不可用、索引过期等必须显式报告；需要保留的字面回退标为降级，不能冒充向量检索成功。双域向量分数不假定天然可比。

#### 5B. Desktop 自有 Jev 适配器与配置

- 增加独立的 TypeSafe/Jev 判断服务设置，包含启用开关（默认关闭）、API Key、模型标识和连接测试；高级项提供超时。保存配置与启用调用分开。
- 官方 API 为 POST https://api.typesafe.ai/v1/systemone，Bearer 鉴权，输入 model/state/questions，输出结构化 answers/概率；需专用适配器，不能仅将模型名加入聊天模型下拉框。依据 [TypeSafe API](https://docs.typesafe.ai/api)。
- 密钥沿用项目安全凭据存储边界，主进程调用，日志脱敏；测试连接用固定无私人内容的样例。设置明确提示：启用后查询文本发送至 TypeSafe，知识正文、路径、结果和历史不发送。
- 关闭时零 Jev 请求，直接使用 5A。启用首版仅为观察（shadow），不改变实际检索；观察通过后的实际路由作为后续独立选项，不能把启用观察写成启用智能路由。
- 区分未配置、关闭、可用、鉴权失败、超时、格式错误和低置信度。失败沿用 5A，并记录具体原因；不能让 Jev 不可用阻断基本检索。

#### 5C. 双域观察与路由验证

- 扩展现有 `gateway_auto_context` 的收集与裁决：无检索、Memory、Knowledge、两者。明确指定的领域/模式优先。两域命中共用当前有界上下文预算，长知识只给摘要和继续读取指针；保留 selected、delivered、used 的证据区别。
- 先在观察模式对真实问题标记漏检、误检、双域需要、延迟和失败，再决定实际自动投递。超时、不可用、索引过期与正常零结果分别呈现。
- Jev 只看查询文本与固定选项定义，先做 shadow 对照；正文、路径、结果和对话历史不发送给 Jev。是否赋予实际路由权由对照证据另定。

验收：代表性问题证明四类决定及预算、隐私和失败回退；旧 Memory/InnerLife 行为无退化。自动选中不等于已投递或已使用。

2026-09-22 阶段5源码进度：Desktop 已增加 TypeSafe 专用适配器、默认关闭的观察开关、模型/超时/密钥保存及固定样例连接测试。密钥通过 Electron safeStorage 加密，安全存储不可用则拒绝保存新密钥；公共配置不返回密钥。关闭时不发送请求；启用仅 query-only shadow，结果 applied=false，不参与真实路由。鉴权、限流、超时、格式错误、低置信度等分别报告。

## 首版取舍

- 单个当前目录；支持已有 MD 与新收录，不管理多个库。
- 收录由 Agent 负责语义、Desktop 负责可信写入与可见结果；无后台监听全部对话，也不要求每篇日常笔记弹窗批准。
- 保留外部 MD 编辑能力；Desktop 负责发现变更和索引状态，不在首版提供完整编辑器。
