# 0.7.7 InnerLife 旧念头重复修复计划

2026-09-14；范围：个人 Mac arm64 Lite 测试包，不安装、不公开发布。

## 已确认的问题

旧 open_loops 无日期筛选地进入 Current inner state；新 RSS 能反复触发同一旧事件，
并把旧事说成最近发生。process 的去重主要比较 inbox 素材。event 没有保存完整生成
上下文，无法从 memoryIds 推断模型是否读过某个事实。

## 实施顺序与验收

1. **上下文选择**：为生成单独投影内部状态。未标日期、超过 30 天、未来日期、
   已关闭或与当前 inbox/明确请求无关联的 loop 不进入生成；不使用 profile 更新时间
   给每个旧问题续期。保留原数据，记录选择/排除原因。日期代表问题复核时间，不代表
   用户事件发生时间。无独立日期的 mood/focus/interests 不再自动当作当前事实。
2. **事实与时间边界**：所有 InnerLife 系统提示区分观点、问题和事实；旧 thought
   不是用户事实证据。主要 process 路径增加独立生成后审核，要求个人事实对应输入
   sourceId 和原文引句；校验来源和引句，拒绝无支持、时间错置和重复观点。
   审核使用现有模型配置，不增加依赖。模型审核是防线，不承诺语义零误判。
3. **重复和失败处理**：保留素材去重，同时比较最终正文，并给审核传入近期同 Agent
   念头供语义重复判断。模板/调用失败/审核格式错误不能创建 share；调用失败保留
   inbox 待重试，明确记录原因。探索/收敛路径也检查同类绕过问题。
4. **可审计性**：记录实际生成与审核输入、策略版本、来源时间、选择结果和判定。
   上下文有长度上限；超限保留失败结果，不把不完整输入当作通过。
5. **回归**：临时数据根运行旧状态隔离、近期相关状态保留、同新闻去重、不同新闻
   同念头去重、个人事实来源缺失/引句不符、时间错置、无分享、审核失败重试、正常
   新内容放行；验证不改历史状态。执行 git diff --check、npm run check 和相关
   InnerLife 非交互测试。
6. **交付**：版本升级 0.7.7，更新说明，E61 生成 Lite DMG，检查包内版本与改动一致、
   Lite 边界及签名/公证结果。用户自行安装并测试实际分享体验。

## 不同于旧行为

30 天是保守的自动上下文资格窗口，不是删除/闭环标准。历史问题仍可显式查阅，
经新材料支持并重新复核后可恢复使用。近期记忆不改为全库语义检索；先修复已证实
的旧状态和去重缺口。现存 pending shares 不自动删除或批量改状态，测试时需区分
升级前旧分享与升级后新生成结果。

对应试验：HCT-2026-09-08-01（失败不可当正常分享），
HCT-2026-09-08-02（状态复核时间不等于事件时间；旧输出不作事实真值）。
