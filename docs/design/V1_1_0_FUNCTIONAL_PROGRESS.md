## 本批完成：日志结果与刷新可靠性

- 助手请求用明确动作名称呈现；不能识别的工具显示“助手请求（未识别操作）”。原始工具名、状态、错误和返回摘要在详情中保留，不改写历史数据。
- 请求完成、检索结果、客户端接收、助手实际使用分别表达。仅完整、可解析且符合已核对接口形状的摘要参与结果解释；截断摘要不修补、不猜测。没有使用证据时不显示已使用。
- 记忆查询零匹配与记忆不存在分开；有匹配只描述本次返回条数。检索降级/错误标为部分完成；`memoria_get` 返回应用错误不会因请求状态 `ok` 而显示完成。未知状态保持未确认，概览显示错误、部分完成及未确认数量。
- 手动和跟随刷新失败进入错误列表，并提示正在显示旧记录。连续失败每个失败周期保留一条错误，恢复后再次失败重新记录。避免并发刷新，离开日志页停止跟随计时器。
- 不完整刷新响应不替换旧日志；筛选、打开详情、刷新失败不再推进“更新于”时间。成功刷新记录实际读取时间。
- 后台检查按已知 code 提供中英文解释；待核对、等待与后台错误保持区别。缺少检查结果不显示“没有异常”；旧英文 message/action 在技术详情可查，不据此自动归档、启用生成或标记使用。
- “网关轨迹 / 衰减审计 / 近期证据序列”在日志入口调整为“助手请求 / 记录与后台检查 / 最近记录”。同步英文与 HTML fallback；不改变后台能力、阈值、写入规则或模型配置。

## 后续完成：助手接入与共同线接续

保持原有样式、布局与品牌，仅使用现有控件样式补充必要操作和状态。

### 助手接入

- 区分本机服务可用、材料不完整、助手请求已观察到、连接检查请求完成及结果未确认。最近请求与连接检查分别注明 Agent、客户端和时间，不将不同客户端的证据混成一次成功，也不宣称持续在线或自动读取。
- 增加“刷新接入记录”。失败保留旧记录并明确待确认，恢复后可再次复制；并发刷新被合并，凭据在复制过程中变化不会误报新材料已复制。
- 接入说明保留当前 HTTP 配置、身份和兼容约定，补充客户端能力限制与凭据用途。显式目标按确切 ID 读取；多条候选只有在用户意图唯一匹配时选择，否则询问，不为接入激活另一条线。示例不自动保存，不要求任务或下一步。
- 连接检查改用现有 `getInnerLifeDaemonStateReadOnly`，不再顺带创建想法配置或后台状态；没有新增模型、生成调用或自动化。

### 共同线接续

- 读取成功且当前记录有内容时，可复制该线的接续提示。提示仅包含准确 ID 与读取/讨论说明，不携带旧正文、凭据或身份冒用指引；助手须以自身身份读取并核对目标，按需跟随截断结果的详情引用。复制不等于已发送、已读取或已使用，也不授权修改记录。
- 切换中、读取失败、概览未加载、返回 ID 不符或空记录时禁用接续复制。失败可重试刚才请求的准确目标，不能因页面保留旧内容就复制旧话题。切换后到达的旧复制回执不覆盖新选择。
- 身份筛选变化会清除不匹配的阅读选择并使旧请求失效；不激活或修改任何共同线。既有请求版本保护保留。
- 当前记录有明确下一步才显示该段；显式空值优先，不从旧 metadata 或历史 handoff 恢复计划。首页与完整阅读页口径一致。草稿、待核对与标记待更新的记录有文字提示，仍保留 Understanding、历史及引用。
