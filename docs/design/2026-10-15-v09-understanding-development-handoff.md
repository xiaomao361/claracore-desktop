## 用户已确认的方向

- Gateway 提供基础方法；共同理解是面向当前事情/对话的上层上下文包，理解层组织读取及后续写回。
- 四模块职责保留，不预设新增一份独立权威事实库或第五个业务模块。
- 知识：接触了什么资料、有什么依据可以再次查阅。资料立场不等于用户立场。
- 记忆：关于用户和共同经历确认了什么、决定了什么。推测不能当作用户确认。
- 共同线：理解在哪件事中发挥作用、走到了哪里、下次从哪里继续。
- 内在活动：已有材料和经历间产生的值得讨论的新联系。继续自主推演，不由理解层代写念头或强行产生内容。
- Agent 当前不知道该写什么，容易写了一个模块忘记另一个。要把选择、去重、路由、完整性和回执落到产品契约，不能只增加提示词或重命名工具。
- 读取：定位共同线（适用时），召回必要知识与记忆，选择适合当前交流且允许分享的内在活动；过程中可继续补读。
- 写回：Agent 提交本轮真实变化与证据，理解层决定各模块需要做什么，执行授权内的更新并逐项报告。
- 包里可以有分歧、疑问与待核实想法，统一称“共同理解”；“共识”只指已经达成一致的部分。

## 最新问题：共同线生命周期

用户正在询问无共同线时是否新建、对话结束是否关闭、短期与长期是否区别对待。
以下是交接时给出的建议默认，尚不是用户逐条确认的新业务制度；开发 chat 应先用简短说明澄清边界，在不扩大权限的前提下实现保守路径：

- 以“存在值得恢复的具体事情/目标/持续关切”为建线依据，不以聊天次数或持续天数为依据。
- 有匹配线就复用；多个可能目标不得静默选择、激活、合并或重排。
- 无匹配线且确有可恢复事项时，可以在明确意图及既有授权内创建；读取本身不创建线。
- 一次性问答、普通闲聊可以无共同线，仍可读取或按授权保存记忆/知识。无共同线不能阻断理解包。
- 短期任务也可以建线；长期事项可以跨许多 chat 共用一条线，无需第一版增加长期/短期强制分类字段。
- 对话结束是保存进展的时点，不等于事情结束。事项完成或明确终止才关闭/归档；先保存最终位置，保留历史。
- 等待用户、等待外部结果、暂停聊天、空闲时间久、暂时没有 nextStep，都不能单独证明完成。
- 重要决定/进展支持增量保存，不只依赖最终结束事件；宿主没有结束回调时必须如实描述限制。

## 建议实现边界与验收

具体 API 名称、内部结构和分步实现由开发 chat 核对源码后决定；以下是需要保证的行为：

1. 面向当前问题返回有界、可追溯的共同理解包。包括适用的当前位置、确认事实、来源依据、未决问题、可分享想法和深入读取指针；不要求四类齐全，不合并成无来源叙述。
2. 一个统一变化提交路径，接收有出处/说话者/确认状态的本轮增量。Agent 不需要自行调用四套写入流程；理解层检查已有对象并形成可检查的处理计划。
3. 需要真实说明谁负责语义提取/判断、判断依据和不确定时的结果。不能用关键词硬判“用户确认”，也不能把所有分类责任交回 Agent 后宣称已解决遗漏。
4. 优先复用现有模块 facade 和已有模型配置；不默认启用 Jev/决策模型、添加外部服务、费用调用、后台全对话采集或更改宿主自动注入契约。
5. 写入沿用现有权限、归属与证据边界。已有授权内常规操作不反复问；推测、冲突、缺证据/授权返回明确待处理项，不伪装成确认或无变化。
6. 跨域操作返回每项已完成、无需变更、待补证据/授权、失败或部分完成及恢复引用。可安全恢复，传输丢回应重试不能产生重复记录。不要宣称跨 SQLite/Markdown 原子事务。
7. InnerLife 保持自主性、私有内容和分享时机边界。按既有机制传入材料与向用户分享想法是不同操作；收集或选择不等于已交付或已使用。
8. 同一事实不全文复制四遍，依靠稳定对象引用建立联系。保留现有直接工具供深入读取/维护，普通 Agent 使用统一路径。
9. 更新 Agent-facing 指南与相关契约，描述何时读取、何时提交、无共同线的正常路径和未集成宿主边界。

关键回归场景：无共同线一次性问答；已有线恢复；多候选歧义不写；短期事项建立到完成；长期线跨 chat 保留；用户确认与 Agent 推测区分；重复提交；部分失败恢复；无新知识不写；未允许分享的想法不泄露；有界响应。
只用替身/fixture 证明的效果与真实模型提取质量、宿主集成、用户业务验收分开报告。
