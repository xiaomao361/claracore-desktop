## 上轮结构：概览入口与独立弹窗（本轮已修正）

用户反馈上一版设置页结构不清晰、与其他页面表现不一致，随后明确同意修改。现在主页面按「应用」「模型与助手」「资料与数据」分组，九个入口仅展示用途、已保存值或状态与设置按钮。表单统一进入复用现有视觉的原生详情弹窗，一次只编辑一项；没有总保存按钮，也不在编辑弹窗中再嵌套编辑弹窗。关于页面只读，其余八项独立保存。

- 记忆检索和想法生成分别收集、校验、保存自己的字段。另一项未配置不会阻塞；原有显式读取模型、草稿版本、过期请求和凭据保护保留。
- 保存并刷新成功后返回概览；后续新输入仍留在弹窗。失败保留输入与具体结果；已保存但刷新失败和保存未确认分开提示。
- Esc、关闭、取消和背景点击统一处理未保存修改，窗内提示继续编辑或放弃。正在保存或执行目录选择/数据操作时阻止关闭；关闭后焦点回到对应入口。实际系统键盘行为待用户观察。
- 资料目录选择与清除先形成草稿，只有点击保存才写入；取消恢复已保存目录，失败可重试。概览读取已保存状态，不显示未保存草稿或凭据。
- 备份设置的底部保存按钮仍绑定原表单，保留校验、备份/导入/恢复确认；数据目录重启与不搬迁语义不变。只读路径与运行信息继续作为次要详情收起。
- 删除旧标签导航逻辑和对应样式，设置弹窗生命周期集中在 [settings-dialogs.js](../../app/settings-dialogs.js)，配置与业务逻辑继续留在现有视图/事件模块。

新增内存 DOM 回归检查覆盖九项入口、独立保存、关闭防护、焦点返回、保存期间新草稿、真实渲染模块注册、资料目录暂存/放弃/失败重试及独立模型载荷，已纳入 `npm run test:settings:workflow`。这类测试不启动应用窗口，不证明视觉或真实键盘验收。旧 UI 回归脚本已改用新入口，本轮未运行。

以下表格和旧包记录保留早一阶段的底层修复依据；旧「切换设置标签」观察方式已由独立弹窗取代。当前观察重点是：分组是否清楚；进入任一项、保存返回和放弃修改是否自然；长表单及深浅色的显示是否完整。

## 已完成

| 方面 | 原问题 | 当前行为 |
| --- | --- | --- |
| 文案 | 智能能力、向量、Memory Controller、canary 等表达要求先理解机制 | 改为模型与想法、检索模型、自动提供记忆和试行提供；高级协议与身份范围仍保留准确含义 |
| 依赖说明 | 模型配置与后台生成容易混为开启功能 | 单独提供后台生成开关；说明基础存储/阅读不需要生成模型，模型检测只验证地址和模型列表 |
| 模型输入 | 想法模型只能从已读列表选择，列表刷新可替换模型 | 使用输入框与候选列表，支持手填；读取候选不修改已填写模型 |
| 请求时机 | 地址失焦/切换提供方会自动请求服务 | 只在点击读取列表或检测时请求；渲染和编辑不请求模型服务 |
| 表单草稿 | 后台快照刷新会覆盖模型、外观、目录、连接和自动回忆方式的未保存输入 | 按表单范围跟踪草稿；保存回执只确认对应版本，新输入继续标为未保存 |
| 模型状态 | 修改地址、密钥或模型后，旧连接检测仍可能显示有效 | 配置变化即失效；过期请求的列表或检测结果不能覆盖新配置 |
| 失败状态 | 列表失败会清空候选；异常响应可能被当作正常空列表 | 保留原输入与候选；有效空列表、结构错误、网络错误分别处理 |
| 保存反馈 | 写入完成但刷新失败也笼统显示保存失败 | 区分已保存但刷新失败、保存未确认，以及保存后又有新输入 |
| 输入校验 | 分钟显示四舍五入，数字解析会接受尾部垃圾或截断小数 | 90 秒显示/保存为 1.5 分钟；正整数秒与时段严格验证，不静默代入默认值 |
| 数据目录 | 保存后重启提示可能在刷新时消失 | 对比当前目录和下次启动目录持续判断；环境变量指定目录时禁用修改并解释 |
| 自动回忆范围 | 只改模式会把定制身份名单覆盖为所有助手 | 只保存模式，保留已有身份范围；配置异常明确提示待检查 |
| 备份设置 | 保存中的新输入可能被较早回执清除 | 备份表单同样跟踪输入版本，保留后续修改；原有恢复/备份安全流程不变 |
| 代码结构 | 旧摘要节点、隐藏的记忆密钥字段和重复接入配置入口已不在界面中，但仍维护代码 | 删除这些 UI 绑定及逻辑，保留后端兼容字段和已有数据 |

新安装设置及密钥行使用仅插入缺失项的初始化逻辑，不新增清空旧配置的迁移。已有安装中保存的模型、后台开关及密钥引用不变；源代码移除共享默认值不等于轮换远程账户密钥。

设置与密钥引用在同一 SQLite 事务中保存，任一写入失败均回滚。没有扩大成数据库/Markdown/外部服务的跨域事务。模型变更需要重新准备搜索数据时仍保留原记忆及确认流程；更换地址也计入该判断。
