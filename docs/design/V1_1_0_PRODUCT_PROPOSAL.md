# ClaraCore Desktop 1.1.0 产品设计提案

> 发布说明：本文保留 1.1.0 规划时的背景；已采纳功能在 1.0.6 交付，当前状态见[发布记录](../RELEASE_1.0.6.md)。未采纳方案不代表当前实现。

## 1. 推荐结论

**把软件从“展示共同理解的模块”改成“看见上次留下的内容，并能在常用助手里接着聊”。**

对外定位：**换个对话，也能接上之前的事。**

首次解释：ClaraCore 帮你和常用 AI 助手保留确认过的信息、持续聊的话题和可回看的资料。你仍在原来的助手里交流，在这里查看留下了什么。接入与自动读取能力取决于所用客户端。

推荐保留品牌、现有领域边界和数据；重做首页信息顺序、首次接入路径、共同线阅读结构及日志表达。不要只做换色或批量替词。共同线暂保留原名，以具体话题解释它，不改成“项目进展”。Understanding 保留，解释与引用在相关内容下展开，不独立占首页主画面。

首页的一个主动作是“查看这条共同线”。“接着聊”不能伪装成 Desktop 自带聊天或已把上下文发给助手：使用复制指引，明确用户下一次要到哪个客户端操作。

## 2. 场景盘点：用户想做什么

以下为源码走读与设计推演，不是已完成的用户可用性测试。生活、工作、查阅是检验场景，不新增三套导航或强制分类。

| 场景与目的 | 当前入口及可见结果 | 已确认障碍 | 1.1.0 行为与判断标准 |
| --- | --- | --- | --- |
| 生活：反复聊阳台植物，想知道之前观察到什么 | 首页主题、共同线当前位置、记忆 | 首页将共同线解释为“进展与下一步”；详情为过去/现在/接下来三段 | 标题“阳台上的植物”；正文“最近观察”；没有计划也能完整阅读，不催更新或补任务 |
| 生活：希望助手记住旅行偏好 | 助手显式保存；记忆页阅读与查找 | 四模块介绍先于具体用法；第一次不知向谁输入 | 接入后给一句可复制示例，清楚说明由助手处理；保存结果指向实际记录；不自动写入演示偏好 |
| 工作：隔周继续准备一份培训材料 | 共同线、资料、记忆中的约定 | 相同内容散落；首页四模块连接图要求先理解架构 | 一条共同线呈现“上次聊到哪里”、已记录约定、引用；只有记录里有行动时显示“接下来” |
| 工作：换助手继续一个具体事务 | 接入说明、Agent 身份、共同线 | “接入就会连接”的表达容易超出客户端能力；连接与实际读到混淆 | 分开显示本机服务、客户端接入、读取结果；保留身份隔离，不能以换助手为由开放其他身份内容 |
| 查阅：找回一篇看过的文章及出处 | 知识页目录、原文/含义/混合搜索 | 语义索引准备容易被理解为软件整体不可用 | 导航改为“资料”；先可浏览和按原文查找；语义能力未准备时只解释该搜索方式不可用，不能静默切换并冒充语义结果 |
| 查阅：想知道助手刚才有没有找到旧内容 | 日志、网关调用、回执 | 工具名作标题；`ok` 被直接显示；缺失状态默认 `ok` | “查找记忆 · 请求完成”；另列检索与返回结果；实际使用无证据则“未确认”，不能从调用推导 |

## 3. 信息结构与对象关系

侧栏按阅读目的排列：**首页 / 共同线 / 记忆 / 资料 / 想法**。下方分组：**连接助手 / 日志 / 设置**。这些是推荐标签，不是已修改的导航。

- 共同线保存一个话题的上下文及其变化。它可以是生活观察、长期兴趣、工作事务；不要求截止日期、下一步或“完成”。列表用标题与最近记录表达，不新增任务类型字段。
- 记忆保存可单独找回的信息。用户确认、来源记录、生成解释仍须可区分，不将旧数据批量标为用户已确认。
- 资料保存带出处的原文。引用打开相应来源，不把所有资料转为记忆。
- 想法对应 InnerLife 的可选生成与分享。它不代表事实，也不代表助手已说过或已使用。
- 同一对象可有已记录引用；没有引用就不画关联。相关内容只展示已有关系，不开启自动全库关联、跨身份搜索或后台生成。

保留 / 后移 / 合并 / 待核查：

| 处理 | 内容 | 理由与边界 |
| --- | --- | --- |
| 保留 | Memory、Continuity、Knowledge、InnerLife、Understanding、Gateway | 职责不变；日常标签简化不等于协议改名 |
| 重组 | 首页四模块汇流图、重复内容入口、主题选择 | 让具体内容成为主角；品牌线只作阅读结构装饰 |
| 后移 | 角色设定、技术 ID、生命周期统计、维护参数、原始日志 | 放相关详情或设置高级区，入口可发现，不能删底层功能 |
| 合并展示 | 日志流与“近期证据序列”的重复时间线入口 | 默认一条事件流；内容变化/后台检查作为筛选，不丢历史、来源或类型 |
| 待核查后实施 | 跨模块事件去重、分页来源、部分回执缺失 | 以稳定 ID/来源去重；未证明同一事件时不得仅凭相似标题合并 |
| 不纳入 | 统一聊天框、任务看板、默认远程模型、自动保存所有会话 | 超出当前定位与授权 |

目录维持有界读取：一般目录默认 10 条、明确请求最多 50；首页最多 3 条主题预览。选择一个对象后再读详情，不能为了首页生成全量快照。详情保留语义完整性，不将字节上限当成压缩一切内容的目标。

## 4. 首次使用：先获得一个可信结果

**步骤 A：知道在哪里交流。** 首页空态“把之前的事，带进下一次对话”。说明“在你常用的助手里交流，在这里查看留下的内容”。主按钮“连接我的助手”，次入口“先看看界面说明”。说明中的示例标为演示，不写入用户数据库。

**步骤 B：取得连接材料。** 接入页用三步：复制接入说明 → 按客户端能力配置 → 在助手里检查连接。保留现有复制材料实现方向；用户复制前说明材料含本机连接凭据，应只交给信任的客户端，不公开展示 token。客户端不能自行改配置时提供明确配置说明，不保证一键接入所有客户端。高级 HTTP、身份和 profile 配置折叠。

**步骤 C：区分连接结果。** 本机服务就绪只是可接入；实际连接测试成功才显示“助手已接入”；没有近期请求显示“尚未观察到助手请求”，不是离线。读取测试只读，不创建内容。显示最近一次检测时间与客户端范围，不使用一个永久绿色“在线”徽章。

**步骤 D：按用户选择留下一条真实内容。** 提供两条任选示例：“请记住：我照料植物时更喜欢简单、低维护的方法”“把我们关于阳台植物的讨论留成一条共同线，不必列下一步”。用户自行改写并交给助手；不预选、不自动发送。结果只有在相应记录可读时显示“已找到这条记录”。未找到是“暂未查到保存结果”，要查看助手结果或重试读取，不能直接断言未保存。

**步骤 E：完成一次接续。** 在共同线详情复制“请读取共同线〈标题〉（ID）再接着讨论；以实际读取结果为准”。复制成功只显示“继续讨论的提示已复制”，不能显示“已发送给助手”。换对话后实际读取/使用由宿主观察确认，不由 Desktop 模拟通过。

用户可跳过引导阅读已有内容；连接设置或可选模型故障不遮挡无关路径。

## 5. 关键界面与交互

### 首页：最近留下的内容

结构：标题“上次聊到哪里” → 最近查看/更新的共同线预览 → “查看这条共同线” → 记忆与资料入口 → 小型连接状态。第一次进入不擅自选定一个全局活动共同线；默认可取有权限的最近更新条目作预览，并标“最近更新”，用户选择只改变 Desktop 阅读对象。

宽窗口用主阅读区加窄侧区；侧区只显示已记录引用的预览及“连接助手”。没有引用时不占一个大空卡。窄窗口改为单列，主内容在前。新用户无共同线走首次使用空态，有记忆但无共同线时提供记忆入口，不能说“你还没有内容”。

现有里程碑查询仅匹配 release/milestone 等标签，不是全体最近活动。推荐从首页主区撤下专用里程碑列表，既有记忆继续可查；如果以后增加“最近记忆”，必须新建明确有界的数据选择口径，不能把 `homeMilestones` 换名冒用。首页无需新增这个区块即可完成 1.1.0 核心路径。

### 共同线：先读内容，再看变化

列表显示标题、当前摘要、更新时间及记录状态；默认不突出数量。顶部保留身份筛选，不跨身份聚合未授权内容。保留已归档入口，用“已归档”而非“已经完成”，避免假定归档都是完成。

详情顺序：主题标题 → 最近记录与更新时间 → 已记录的认识/约定（按实际内容命名）→ 可选的接下来 → 引用 → “查看记录变化”。用连续阅读页代替三张等权时间阶段卡。待核实状态放在相关段落旁，并可见“读取前请核对”提示；不能靠日期自动宣判内容过时。

“接下来”仅在现有字段有实质内容时显示。字段缺失、明确没有计划、读取失败不可混为“暂无下一步”。完整加载且无字段时可省略该段，页面不提示“请补充”。示例：长期读书话题只需“最近的理解”和引用，工作培训则可以有“接下来：收集两位同事的反馈”。

原只读边界保留；需要更新时提供“复制给助手的更新提示”，不是伪造一个直接编辑按钮。历史页保留证据、快照、原始字段与来源；Understanding 记录在相关段落下按需展开，不删除数据或接口。

### 日志：发生了什么，结果是什么

默认标题“日志”，说明“查看助手请求和本机运行结果”。顶部只显示当前已加载范围：“最近记录中有 2 次失败 · 更新于 10:32”；不能从有限样本声称系统完全正常。空态为“当前范围没有记录”，加载失败为“日志未能读取”，显示旧数据时标更新时间与读取失败。

事件行：时间 / 中文动作 / 具体结果 / 查看详情。筛选“全部、失败、助手请求、后台运行、内容记录”；跨源内容事件的可用性需随实现核查，不承诺尚无数据的筛选有完整历史。默认有界分页，禁止先取全库再前端截断。保留手动刷新；是否沿用页面可见时两秒跟随，按独立性能测量决定，离开页面必须停止。

详情第一层“结果、影响、可用操作”；第二层“技术详情”含工具名、状态码、ID、耗时、原始请求/响应的现有脱敏形态。未知工具用“助手请求（未识别操作）”，不得猜动作；未知状态用“结果未确认”，不默认完成。任意原始错误不做不可靠的自动翻译或当 HTML 渲染。

| 原事件或证据 | 默认呈现 | 不能写成 |
| --- | --- | --- |
| 工具返回 `ok` | 请求完成；检索结果另列 | 记忆已命中 / 已使用 |
| 查询执行成功、候选为零 | 未找到符合本次查询的记录 | 你没有记忆 |
| 自动上下文 abstain | 本次未提供记忆，并显示可识别原因 | 读取失败 / 成功记住了 |
| 有返回正文、hostDelivery unknown | 已准备返回内容；客户端接收未确认 | 已注入当前对话 |
| 有协议返回证据 | 请求已返回；实际使用未确认 | 助手已经理解 |
| 有满足契约的使用反馈 | 已报告使用，并显示反馈来源 | 根据调用推断已使用 |
| 可选后台生成关闭 | 后台想法生成已关闭 | 服务故障 |
| 旧记录长期未更新 | 较久未更新，可按需核对 | 必须处理 / 内容已失效 |

“衰减审计”推荐改为“记录与后台检查”。代码实际包括闲置记忆、共同线状态、等待分享/输入、生成任务错误，并非都属于时间衰减。按 `code` 本地化标题与解释，保留原 message/action 在技术详情；把待核对/等待与执行失败分开。年龄阈值不等于出错；界面不直接采用旧 action 提议自动启用、归档或标记使用。

## 6. 全局术语与文案规范

推荐词表用于下轮实现；中文标签变更同步英文，协议/API 名称保持兼容。

| 当前词 / 内部名 | 推荐日常标签 · English | 解释或位置 |
| --- | --- | --- |
| 共同理解（首页） | 首页 · Home | 首页主标题“上次聊到哪里”，不是宣称已理解 |
| 共同线 / Shared Line | 共同线 · Shared lines | 副文案“持续聊的话题，以及上次留下的记录”；具体标题先行 |
| Memoria / Memory | 记忆 · Memory | “留下的信息、偏好与决定”；状态和来源单独呈现 |
| 知识 / Knowledge | 资料 · Sources | “可回看的原文和出处”；索引不是原文备份 |
| 内在活动 / InnerLife | 想法 · Reflections | “可选生成的想法，未经确认不作为事实”；内部名放帮助 |
| 智能体接入 / Gateway | 连接助手 · Connect an assistant | Gateway 仅技术详情保留，Agent ID 是身份字段 |
| 网关轨迹 | 助手请求 · Assistant requests | 包括连接和维护调用，不统称记忆活动 |
| 近期证据序列 | 最近记录 · Recent records | 只表示当前已加载记录，不能承诺全量事件历史 |
| 消化运行 | 想法生成记录 · Reflection runs | 描述 digest 处理；失败/部分生成需分别呈现 |
| Memory Controller | 自动提供记忆 · Automatic memory context | 设置高级区；不暗示每次都会提供 |
| 受信 canary | 向已认证助手试行提供 · Trial delivery to authenticated assistants | 保留试行、身份和适用范围；不译为“安全模式” |
| 仅观察 | 仅记录判断，不返回记忆 · Observe without delivery | 与关闭、实际返回有区别 |

设置分“连接与身份 / 搜索与模型 / 想法生成 / 数据与备份 / 外观 / 高级”。按当前实现映射，不新增一个总“开启 AI”开关。基础存储与阅读不依赖生成模型；Memory embedding 可以本地/配置 provider/关闭，关闭后可用搜索方式须以真实接口为准，不能承诺任意降级均可用；资料语义查找只允许既有本机能力。Lite 不自动下载模型。想法生成是另一项可关闭能力，远程 provider 的内容去向单独提示。助手订阅不等于第三方 API 额度。

每页覆盖：标题、说明、主/次按钮、筛选、空态、加载态、失败、关闭、未配置、部分结果、来源/时间与详情。错误格式为“哪个动作未完成 + 已知影响 + 当前可执行操作”；没有已知修复方法时给错误详情，不臆造“重启即可”。

实现盘点范围：`index.html` 静态 fallback/aria/title/placeholder，`app/i18n/zh.js` 与 `en.js`，所有 `app/views/` 硬编码、接入材料模板、IPC 反馈、后台 reason/message/action 与设置说明。表中候选不能代替全量逐条审校。英文保留与中文相同证据强度，禁止 `success` 一词覆盖所有结果。

## 7. 视觉方向：保留什么，重做什么

**推荐 A：紫色书页。** 保留开口 C、线与端点、现有紫/冰蓝色族。用内容像书页一样展开：深紫标题、偏中性的浅色阅读面、大块连续文本和细小来源标记。品牌线只用于当前主题的标题边缘或静态分隔，不再让架构汇流图成为主视觉。吸引力来自具体话题、阅读节奏和可信反馈。

| 比较 | A：紫色书页（推荐） | B：现有界面轻量整理 |
| --- | --- | --- |
| 保留 | 标记、配色方向、领域/协议、已有主题能力 | 原页面骨架及大部分卡片 |
| 调整 | 内容优先首页、单篇阅读详情、接入三步、日志结果层 | 删除重复说明、改词、压缩状态区 |
| 收益 | 新用户先读懂内容与动作，卖相变化可感知 | 变更小、能较快消除术语问题 |
| 代价 | 需处理布局、状态与键盘路径，回归较多 | 原有模块主导与任务式阅读仍明显 |
| 决策 | 作为 1.1.0 主方向，先做三个关键面 | 用于设置/低频维护面的保守改造，不单独当成整体重设计完成 |

建议视觉规格（待真实界面验收）：保留主墨色 `#443256`、品牌紫 `#795bac`、端点蓝 `#6088b0`；浅面沿用 `#f6f3fc` 系统，正文阅读面接近白，减少满屏淡紫卡片。深色沿用 `#282333` / `#e5dcf3`，层级以明度和间距区分。紫色不充当成功/错误状态色。

系统字体优先，不增加在线字体或重型插画依赖。正文 15px/1.65，列表 14px，页标题 28–32px，8px 间距体系；标题不全大写。阅读行长约 36–44 个汉字，避免桌面拉伸成一行超长。容器圆角 12px，少用多层套卡和阴影。示意稿只是方向，颜色对比须在实现时验证，不能凭色值宣称达标。

宽度策略：可容纳时使用约 176px 侧栏和弹性阅读区；不足时折为图标加可访问名称的紧凑侧栏，进一步不足改为可展开导航。共同线列表/正文在内容无法保持可读时变为列表到详情两级；返回保留筛选与滚动。窄窗口不水平滚动整页，技术原文可独立横向滚动。断点用实际容器压力确定，并在 720/960/1280 及应用支持的最小窗口验收。

动效只用于直接操作后的 120–180ms 状态过渡，首页不循环呼吸或持续绘制。减少动态时立即切换。键盘能依次到导航、筛选、内容和操作；焦点清晰，弹窗关闭返回原触发点，错误信息可被读屏感知。长标题换行，状态同时有文字，不能只靠颜色。

宣传素材可使用静态品牌线与真实内容构图；所有概念稿标注设计。不得将宣传画面当成应用实际能力或设备验收。
