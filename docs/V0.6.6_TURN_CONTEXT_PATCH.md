# ClaraCore Desktop v0.6.6 Turn Context Patch

> Status: server side implemented 2026-08-07; host adapters not done
> Scope: make automatic context one server-owned MCP call
> Non-goals: UI, packaging, signing, Shared Line cleanup, hook-session cleanup

## 1. Current Truth

v0.6.6 successfully reduced the default MCP and product-context payloads and
added `gateway_auto_context` as the single-winner arbiter. The remaining
automatic path still leaves too much orchestration in each host hook:

1. call `memory_context`;
2. list and check pending InnerLife shares;
3. translate both domains into candidate shapes;
4. assign share relevance in the hook;
5. call `gateway_auto_context` and inject its block.

Directly driving the Codex hook proves that this can select one bounded winner
or abstain. Real Codex Desktop acceptance did not complete: after restart and
two real turns, `SessionStart`, `PreToolUse`, `PostToolUse`, and `Stop` fired,
but `UserPromptSubmit` did not. Its configuration and trust hash are present.

The v0.6.6 byte shaping and arbiter are working. The design gap is that
candidate collection and scoring live outside ClaraCore behind a host event
that is not reliable on every client path.

## 2. Smallest Patch

Do not add a twenty-seventh core tool. Extend the existing
`gateway_auto_context` input:

```json
{
  "prompt": "the current user message",
  "sessionId": "optional InnerLife session id"
}
```

When `prompt` is present, the Gateway owns the full flow:

1. derive Agent/client/conversation identity from the authenticated caller;
2. run Memory Controller with its current canary, sensitivity, temporal, and
   same-Agent gates;
3. inspect only the default three pending InnerLife candidates;
4. evaluate InnerLife relevance against the prompt without guessing among
   active Shared Lines;
5. normalize candidates inside ClaraCore;
6. call the existing `arbitrateAutomaticContext` implementation;
7. return one bounded block or abstain.

Keep `memoryCandidates` and `shareCandidates` as a compatibility/test path. If
`prompt` and candidate arrays are supplied together, reject the ambiguous
input or define one explicit precedence rule; never merge them silently.

This preserves:

- core at 26 tools and below 12 KB;
- the existing tool name and result shape;
- the 600-token target and 900-token hard limit;
- one relevance policy across Codex, Claude Code, and Hermes;
- `selected`, `delivered`, and `used` as separate evidence states.

## 3. Important Boundaries

### InnerLife scoring and writes

The current Codex hook derives a numeric share score from timing-check
metadata. Move that policy into a maintained ClaraCore adapter/service. Hosts
must not invent their own weights.

Automatic evaluation must not create Memory, update Shared Line, change share
status, or create InnerLife content. Avoid persisting the full prompt once per
candidate; prefer one bounded aggregate audit row or safe hash/preview fields.

### Shared Line

Shared Line remains explicit in this patch. Automatic prompt context must not
select one of many active lines or inject Agent state.

### Failure behavior

- total work should finish within 3 seconds;
- failure in one domain may still allow a winner from the other;
- identity failure, total timeout, or arbiter failure returns abstain;
- no failure may fall back to unbounded context;
- traces record ids, decisions, reasons, bytes, and latency, not full bodies.

## 4. Host Adapters

### Codex Desktop

Keep `UserPromptSubmit` as the preferred deterministic path when it is emitted,
but reduce it to one call:

```text
gateway_auto_context({ prompt })
```

For the current Codex Desktop path, use the working `SessionStart` hook to add
one compact session instruction:

```text
At each user turn, call gateway_auto_context once with the current prompt. Use
its block only for decision=deliver_one. Selection is not delivery or use.
```

This fallback is model-driven and must be labelled best-effort. Gateway traces
must show whether the call actually happened. Do not use `PreToolUse`,
`PostToolUse`, or `Stop` as fake prompt hooks; they occur after the first model
decision.

### Claude Code and other hosts

Claude Code's prompt hook should call the same single tool and inject only
`block.body` for `decision=deliver_one`. It must not independently retrieve
Memory, inspect InnerLife, or reproduce scoring. Other hosts use the same
contract through either a prompt hook or a compact session instruction.

## 5. Acceptance

### Server

- Prompt-only calls cover Memory win, InnerLife win, suppression, and abstain.
- At most one block is returned and budgets remain enforced.
- Restricted, historical, cross-Agent, weak, stale, and non-pending candidates
  remain fail-closed.
- One domain failure does not discard a valid winner from the other.
- Automatic calls do not mutate product state or duplicate full raw prompts.
- Core remains 26 tools and below 12,288 serialized bytes.
- `npm run test:context-budget` and `npm run check` pass.

### Clients and installed runtime

- Codex direct hook smoke: relevant prompt gets one block; unrelated prompt
  injects zero bytes.
- Claude Code makes one MCP call per prompt, not independent domain calls.
- Codex SessionStart injects only the compact calling rule, not product data.
- Real client traces distinguish missing call, abstain, selected, delivered,
  and used; missing evidence is never reported as success.
- After source acceptance, install the patched Lite app, reconnect clients,
  confirm the prompt schema, and repeat relevant/unrelated tests.
- Signing and public-release acceptance remain separate unless authorized.

## 7. Implementation Result (2026-08-07)

Implemented on branch `v0.6.6-turn-context`. Three source facts the proposal did
not account for changed the shape of the patch:

**The trace layer stored the raw prompt.** `gateway_traces.request_json` persists
the whole argument object. Passing `prompt` would have written every user
message into SQLite once per turn — directly against this document's own §3.
`redactGatewayTraceRequest` now replaces `prompt`, `transcript`, and `context`
with a hash plus an 80-byte preview, mirroring the Memory Controller's existing
`query_hash` / `query_preview` shape. Stated honestly in the tool description:
a prompt shorter than the bound is still recorded in full, and `truncated` says
whether anything was actually withheld.

**`innerlife_share_check` writes.** It INSERTs into `innerlife_share_checks`
with the supplied context, so it cannot be the automatic relevance path without
violating §3. `core/innerlife/relevance.js` is a new read-only scorer using the
same token machinery. `share_check` stays the explicit, evidence-producing call.

**The 3 s budget did not fit.** The Memory Controller's own hard timeout is
2500 ms. Domains now get separate slices — 1500 ms Memory, 800 ms InnerLife —
inside a 3000 ms turn, and a domain that overruns is discarded with a recorded
status rather than failing the turn.

Two decisions beyond the proposal:

- **Extend the tool, not the function.** `arbitrateAutomaticContext` stays a
  pure synchronous function with no I/O, which is what makes it cheap to test.
  Collection lives in `core/gateway/turn-context.js` behind injected ports, the
  same pattern `core/gateway/context.js` already uses.
- **`domainStatus` is carried through to the result.** Without it a permanently
  timing-out domain is indistinguishable from a quiet one; an abstain caused by
  a broken domain now reports `no_eligible_candidate_degraded`.

The core profile budget resolved itself: `core` advertises only the host
contract (`prompt`, `sessionId`, `agentId`) and leaves the compatibility arrays
to `full`, so the tool shrank from 542 to 520 bytes and `core` went from 12,195
to 12,173 of its 12,288-byte ceiling.

Memory retrieval is not reimplemented. `runMemoryContext` was extracted from the
`memory_context` handler so both paths share one set of identity, mode,
allowlist, and canary gates.

`prompt` and the candidate arrays are mutually exclusive and rejected together
rather than merged under a precedence rule.

### Claude Code adapter (done)

`ClaraCore/tools/creflex/user-prompt-submit.js` now makes one
`gateway_auto_context({ prompt, sessionId })` call and injects `block.body` only
for `decision=deliver_one`. It no longer retrieves Memory or scores InnerLife
itself. Verified against stub gateways for 0.6.5, 0.6.6, and the patched build,
and end to end against the real patched stdio gateway with a real seeded share:
one arbitrated call, no independent `memory_context`, one labelled block.

No SessionStart instruction was added for Claude Code: its `UserPromptSubmit`
fires reliably, so a model-driven fallback would be redundant bytes every
session.

Two defects this surfaced, both fixed:

- **The relevance metric silently could not fire.** Scoring divided overlap by
  the share's own token count, which penalises length: a realistic
  multi-sentence share scored 0.2 against a 0.5 threshold while a near-paraphrase
  scored 0.55. Only a share restating the prompt could ever have been delivered.
  The denominator is now the prompt — "of the distinctive words the user just
  used, how many does this share also talk about" — with a two-token overlap
  floor.
- **Unrecognised responses did not fall back.** The first version returned
  nothing unless it saw an explicit pre-patch abstain, so a desktop answering in
  any other shape would have injected nothing forever. `domainStatus` is now the
  marker that a desktop actually arbitrated; anything without it falls back to
  the bounded Memory Controller path.

### Not done

Codex and Hermes adapters. Their hooks still orchestrate the old way. §1's real blocker stands: `UserPromptSubmit` did not fire on Codex
Desktop, and no server change fixes that. On a host where that event does not
fire, automatic context is unavailable; the SessionStart instruction is a
model-driven fallback and must not be counted as acceptance.
