# 0.7.7 — 检索、HTTP 接入、可靠维护与 InnerLife 事实边界

2026-09-14；已正式发布为 Latest。最终文件校验值见 GitHub Release 附件。

本次汇总公开版 0.6.14 之后的 0.7.0–0.7.7 更新。

## 升级前须知

- **stdio MCP 已移除**。原来使用 command/args/env 启动服务的客户端需要改为
  Streamable HTTP；在「Agent 接入」复制 URL、鉴权和身份配置。Desktop 需要保持运行。
  默认端口仍为 50668。迁移步骤见 [HTTP MCP 迁移](HTTP_MCP_MIGRATION.md)。
- 支持 HTTP MCP 2026-07-28 和 2025-06-18；不支持 HTTP 的客户端无法继续接入。
- 升级前创建并验证数据备份。数据库新增向量索引/变更跟踪迁移；降级应使用升级前
  的备份，不把迁移后的数据库直接交给旧版覆盖处理。
- 自动备份默认仍为手动；每日备份需在设置中开启。启用后默认保留最近七个自然日
  的自动备份，手动备份与旧版未登记备份不自动清理。

## 0.6.14 以来的累计更新

- **Memoria 检索**：默认 sqlite-vec，按变化 ID 同步索引，保留原始向量；修复当前
  provider/model 下的普通记忆向量覆盖。受限、归档、已删除记录不进入自动生成队列。
- **Gateway**：HTTP 统一接入并共用 Desktop 运行资源；修复交接按调用者选线，
  多线歧义时明确拒绝写入，避免写到其他 Agent 的当前线。
- **数据维护**：可配置每日备份、维护时间、保留天数和可选额外目录。只有备份恢复
  验证及配置的额外副本验证通过，才进入清理；失败保留重试和阶段信息。
- **运行恢复**：唤醒后重算调度，支持当天维护完成后补备份；显示备份、向量覆盖和
  HTTP 工具调用状态，改进可见页刷新并保护未保存的设置。
- **多 Agent 与 InnerLife**：候选先按 Agent 过滤再分页；新增以下事实、时效与重复
  审核，减少旧关系事件被持续包装成新念头。

## InnerLife 修复

旧内部问题曾无条件进入每次生成，新闻虽更新，念头却反复回到同一旧事件，甚至
把几个月前的事称为“最近”。本版保留历史数据，修复生成和待分享入队边界。

- open_loops 仅在自身带有效复核时间、30 天内且与当前输入至少有两个有效词重合
  时进入生成，最多 8 条。不用 profile 更新时间为旧问题续期；无日期的
  interests/mood/focus 不再自动作为当前状态。支持 lastReviewedAt / last_reviewed_at
  或 updatedAt / updated_at；这些是问题复核时间，不是个人事件日期。
- 系统提示明确区分个人事实、推测和旧问题，禁止将旧/无日期事件改写为最近发生，
  禁止把摘要阅读描述成已读完整文章。探索不再拿旧 AI 念头作事实素材。
- process 保留输入素材去重，同时用最终正文去重。正文比较默认阈值 0.82，
  素材比较仍为 0.42；同 Agent 最多 200 个候选，已使用内容窗口仍为 30 天。
- process / explore / converge 在分享入队前，用当前配置模型额外审核一次。
  审核依据原始来源和最近 12 个分享记录（每条最多 700 字），检查无依据个人事实、
  时间错置、换说法重复。个人事实引用必须有存在的 sourceId 和源文原句，代码校验
  引句确实出现在输入中。旧念头和内部疑问不能作为个人事实证据。
- 无模型、生成失败、审核不可用或格式错误不会发布模板；process 保留 inbox 待重试，
  daemon 记录重试失败状态。明确不支持/重复/无分享等判断保留 thought 和事件原因，
  不创建 share。上下文 24,000 字符上限、候选正文 4,000 字符上限，超限不发布且保留 inbox，
  按现有退避重试；持续超限时需要缩小输入或配置状态，不能伪装成已处理。
- event 保存实际生成提示、来源和记录时间、状态筛选理由、审核输入/结果及策略版本。
  记忆正文最多 800 字、inbox 最多 2,000 字；这些是明确的输入摘录，不是完整原文。

收敛过程从所选念头和待分享记录的原始 event 读取来源快照，按当前 Agent 隔离、
去重并限定最多 20 条历史来源、总 JSON 9,000 字符。相同来源同时送入生成和审核；
历史事件没有来源快照时不会把 AI 正文补作证据，来源记录时间不会变成新的事件时间。

实现计划：[V0.7.7_INNERLIFE_PLAN.md](V0.7.7_INNERLIFE_PLAN.md)。

## 验证与边界

自动回归使用隔离临时数据，不修改真实 profile、记忆和历史分享。覆盖旧状态排除、
相关新状态、同输出跨素材重复、事实引用错误、时间审核拒绝、模型/审核失败重试、
无分享及探索/收敛不能发布模板。现有分享生命周期、后台任务和多 Agent 隔离回归
同步验证。新回归纳入 npm run check。

另通过当前配置模型运行五条合成审核样本：无来源个人事件、把旧事说成近期变化、
改写同一观点均被拒绝；一般性观点和有准确日期及来源的历史事实放行。这只证明样本表现，不代表零幻觉或长期体验验收。
语义审核仍依赖模型，可能漏判或误拒；确定性来源校验只能证明引用存在，不能独立
证明完整语义蕴含。每条通过初筛的候选增加一次模型调用。

**升级前的 pending shares 保留原状**，仍可能被取出分享。测试本次修复应看升级后
新生成的 thought/event；不应以旧队列内容判断新生成器是否重复。会话 afterthought
保留现有工作流并使用共同事实提示，本版新增独立审核覆盖 process/explore/converge。

## 本地测试

1. 安装后确认版本 0.7.7；正常使用，观察新生成内容是否还无缘由重复旧事件。
2. 有新相关材料时仍应能产生新观点；单纯换新闻或比喻不应重新包装同一结论。
3. 没有值得分享的内容时允许安静；审核失败应显示 daemon 重试而非生成提示模板。
4. 具体疑点可用 share/thought ID 查 event 的 contextPolicy、generationContext、
   grounding.audit.reviewInput 和 grounding.audit.review 追溯。

源码回归已通过：test:core、test:gateway、test:data-maintenance、test:runtime-recovery、
SQLite 向量两后端、InnerLife 事实审核两后端、会话/后台任务/保留/来源抓取及更新检查。
HCT-2026-09-08-01：超限或模型不可用不会丢失待处理输入，也不会变成正常成功。
HCT-2026-09-08-02：来源快照与 AI 正文分开，记录时间原样传递；来源缺失和预算边界已覆盖。

不承诺该规模的延迟。可用 CLARACORE_DESKTOP_VECTOR_ENGINE=legacy 明确选择旧检索引擎。
