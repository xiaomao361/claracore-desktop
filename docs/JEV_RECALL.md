# 可选 Jev 与双域检索观察

## 用户配置

设置页「智能能力」中的「决策模型」独立于聊天和向量模型。默认关闭。输入 TypeSafe API Key，保存后可通过 `GET /v1/models` 获取该账户可用的模型别名并选择（默认 jev-latest）；保留已保存但暂未列出的模型。可测试连接；观察调用超时可配置 250–5000 ms，自动回召另设 1200 ms 上限；手动连接测试独立等待最多5000 ms，以容纳冷连接。模型列表仅在显式点击获取时请求，关闭且不操作时零 Jev 请求。

- 关闭：零 Jev 网络请求；既有检索继续。
- 开启：将不超过500字符的检索 query（缺省为满足长度限制的 prompt）发送 TypeSafe，仅观察建议，applied=false。
- 显式连接测试：即使关闭也可测试已保存连接，始终使用固定公开样例。
- 留空密钥保留原值，删除需选择删除密钥；不会把已保存密钥回填至页面。

密钥存储在 userData/jev-settings.json 的加密字段中，使用 Electron safeStorage。系统安全存储不可用或使用 basic_text 后端时拒绝保存新密钥。Node-only Gateway 无法解密时明确报告不可用；不会回退明文。已用无窗口 Electron 进程验证本机加密保存与解密读回；跨机器凭据恢复仍需真实环境验收。

模型列表请求由主进程执行，复用安全存储中的密钥，不向页面返回密钥。未配置、加载中、空列表、鉴权、限流、超时、网络和响应格式失败分别显示；失败不修改已保存模型。列表只展示接口返回的别名，当前已保存的版本号仍可保留，参见 [TypeSafe 模型文档](https://docs.typesafe.ai/models)。

## 服务与隐私

专用 POST https://api.typesafe.ai/v1/systemone，Bearer 鉴权。同一请求包含两个固定 choice 问题：回召领域 none/memory/knowledge/both，以及知识检索方式 exact/semantic 的观察建议。请求只包含模型、查询和固定选项定义。正文、路径、搜索结果、会话历史不进入请求；不下载模型，不使用聊天补全文本解析。参考 [TypeSafe API](https://docs.typesafe.ai/api)。

响应有32KiB上限，校验类型、选项集合、有限概率、概率和及置信度。关闭/未配置/鉴权失败/限流/超时/异常响应/低置信度/不可用区分返回；错误不回显请求、密钥或远端响应正文。置信度0.8仅是观察分类阈值，不代表已校准的路由授权。

## 检索与投递边界

`gateway_auto_context` 默认收集两个领域，显式 domain=none/memory/knowledge/both 可缩小范围。Memory 保留 Controller 全部门槛及既有模型配置；Knowledge 按调用方的 mode=semantic（默认）、exact 或 hybrid 查本机索引。Jev 的 `knowledgeMode` 只建议 exact/semantic，始终 `applied=false`，不覆盖调用方模式。两域并行独立超时，失败不阻断另一域。

Knowledge 结果最多3个小节指针，无第二份正文；不同领域分数不直接竞争。默认宿主消费的仍是原 Memory block，Knowledge 输出于 knowledgeObservation 且 applied=false。支持新协议的宿主可显式请求 deliveryContract=memory-knowledge-v1，取得有界正文 blocks；详见 [上下文投递](KNOWLEDGE_CONTEXT.md)。检索执行、候选选中、宿主投递、实际使用保持分开。Jev 输出于 jev 字段，始终不应用建议；domain=none 和 goal_continuation 不调用 Jev。

长 prompt 超过知识查询限制时不会悄悄截断后送出；调用者应提供有界 query。无可用向量或过期索引会显示具体状态，不报告正常无结果。

## 2026-09-22 真实调用记录

使用用户配置的测试密钥，共10次请求，均为固定公开或人工构造查询；没有发送知识正文、路径、私人事实或会话历史。生产配置保持 enabled=false，测试时只在临时目录使用加密配置副本；请求结束后清理副本。全部为 applied=false。

发现与修复：

1. 原连接测试使用1200ms观察超时，首次请求在1221ms超时。手动连接测试改为独立5000ms后成功（3149ms）；自动回召上限仍1200ms，冷连接仍可能明确超时。
2. 原选项将英文 saved notes 误判为 Memory（0.91），中文保存阅读资料虽选 Knowledge 但置信度0.60。修订为 recall-domains-v2：资料归属用户不意味着个人记忆；Both 必须同时需要个人事实与参考资料。

修订后的定点复测：

## 2026-09-22 精确与向量模式核验

新增检索方式观察层之前，Jev `recall_domain` 问题只选择 none/memory/knowledge/both，且 `applied=false`；它没有选择 exact/semantic/hybrid。`gateway_auto_context` 与 Jev 并行启动本地收集，Knowledge 未显式传 `mode` 时默认为 semantic。默认宿主仅消费 Memory block，Knowledge 仍为观察结果。当时一次自动观察返回 Jev `timeout`，没有模式建议可供采用。隔离回归确认调用方显式的 exact/hybrid 能传入 Knowledge，而 Jev 不改变它们。

对当前 `/Volumes/E61/Knowledge` 只读检索的定点结果：`hprof` 精确命中 9 个小节，语义命中 2 个；“频繁的 Full GC 后来自己恢复，应该先观察还是马上动手”精确无命中，语义前 4 项来自对应 FGC 笔记；“垃圾回收次数突然增多时是否应该立刻调整参数”精确无命中，语义前 3 项偏离 FGC 主题。这些是当前语料和索引的检索结果，不是 Jev 模式判断测试，也不足以确定统一阈值。

当时结论：Jev 判断精确或语义的**建议层**可以作为下一步 query-only shadow 试验；正式链路不能声称“回召经过 Jev 选择检索方式”。试验应分别记录 Jev 建议、实际精确/语义/混合结果、命中是否有用，以及超时、低置信度和索引不可用的确定性回退；在真实问题上校验后再考虑应用路由。
